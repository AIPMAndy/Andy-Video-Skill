# 产品宣传片升级：真实 UI + 15 秒样片（V0.4）

目标：把 Andy-Video-Skill 从「能选择视频引擎」提升为「能在出片前检验真实产品证据」。本指南是制作流程，**不是一个已验证的一键 MP4 渲染器**。它不新增未验证的视频模型或 Skill 数量。

## 1. 先选唯一价值，而不是功能报菜名

先明确：给谁看、解决哪个痛点、观众应该记住的一句话、在哪里发布（官网/X/Threads/Reels/小红书）、画幅、明确 CTA。正式首发片、日常功能片、品牌形象片的任务不同，不能用一个模板替代所有创作。

提供项目源码/官网、Logo、一组确认可公开的演示数据、一个只参考镜头关系的优秀样片。Agent 要真实运行产品，从源码或运行中的 UI 获取实际截图/录屏；涉及隐私、支付信息、API Key、联系人、聊天记录时先清理。

## 2. 15 秒固定镜头链（先做小样）

| 秒数 | 镜头 | 证据 |
| --- | --- | --- |
| 0–3 | 完整设备 / 浏览器（device） | 说明场景，让人认出是真产品 |
| 3–10 | 同一设备连续真实操作（interaction） | 给观众看一次实际点击和反馈 |
| 10–15 | 真实结果特写（result） | 结果必须来自实际产品，最后明确 CTA |

不要每讲一个功能就清空镜头、变一台新手机。三条信息线分工：**口播**讲原因、**屏幕短字**讲重点、**真实 UI**完成可核验的证据。生成式模型只补场景气氛，不能生成伪造的软件结果。

## 3. 运行命令（Python 标准库；不需要云端密钥）

从仓库根目录运行：

    python3 00-orchestration/andy-video-director/director.py plan --request "给 SaaS 产品做 Reels 宣传片"
    cp 00-orchestration/andy-video-director/examples/product-launch-brief.json ./my-brief.json

修改 my-brief.json 中的产品、目标观众、价值主张、真实素材相对路径、三段口播和 voice_files。录屏请用公开测试数据，不要泄漏真实用户资料。修改后运行：

    python3 00-orchestration/andy-video-director/director.py promo-init --brief ./my-brief.json --out ./videos/my-product

生成两个文件：product_promo_plan.json（机读分镜表）与 HANDOFF.md（跨 Agent 交接记录）。**没有生成视频**。默认拒绝覆盖已有计划，以免把已经确认的镜头覆盖掉。

声音优先：先生成或录制三段**真实干声**，试听、测时、再安排镜头。请用实际 wav 或 ffprobe 支持的音频文件。时间校验：

    python3 00-orchestration/andy-video-director/director.py promo-audit --plan ./videos/my-product/product_promo_plan.json --assets-root ./

- blocked（退出码 2）：素材不存在、同设备连续性字段不一致、声轨实际时长超过镜头、屏幕短字过长、未确认演示数据安全、商业主张没有证据链接等。修复后重新检验。
- ready-for-render（退出码 0）：文件存在，基础分镜与已提供的音轨时长满足检查。**不证明图片内容真实、影片好看，更不代表 MP4 已生成**。
- 这一步只是磁盘素材门槛。还要人工检查画面、隐私、权利、事实。路径限制为 assets-root 内，阻止常见相对路径穿越。

## 4. 分工与成片

| 环节 | 推荐职责 | 边界 |
| --- | --- | --- |
| Codex / Claude Code | 读仓库、运行产品、真实录屏、资源清单 | 不可虚构真实产品功能 |
| Claude 类模型 | 美术判断、镜头关系、信息层级和逐秒修改 | 需要用真实渲染来检验 |
| Remotion / BB-Video | 程序化动效、合成字幕与配音、导出 MP4 | 先安装对应 runtime / 上游 Skill |
| MiniMax / CosyVoice / 其他 TTS | 真人或合成配音与试听 | 可选，不宣称已接通 |
| Seedance / 其他生成模型 | 实景气氛素材；可用黑屏设备作合成底片 | 不能替代真实 UI |
| ffprobe + 人工验收 | 时长、画幅、字幕、安全与完整观看 | 元数据不能代表审美品质 |

生成的计划必须由**实际已安装的视频工具**执行。合成实景时可在黑屏设备上后期贴入真实 UI，并考虑透视、遮挡与反光；这是进阶工程步骤，**当前脚本不自动实现**。

渲染出视频后再检查：

    python3 00-orchestration/andy-video-director/director.py qa --file ./videos/my-product/preview-15s.mp4 --aspect 9:16 --require-audio

## 5. 六轮协作，不搞一键盲生成

1. **价值决策**：砍掉无关功能，只留一个目标用户与核心价值。
2. **产品取证**：运行源码，录制一次真实操作和结果，确认演示数据可公开。
3. **分镜审美**：定义同设备镜头接力与屏幕可读性；参考作品不复制文案。
4. **声音先行**：分段配音、试听、实测秒数，再调整镜头时间。
5. **15 秒样片**：真正渲染、从头到尾看一遍，记录具体秒数的问题。
6. **锁定迭代**：保存确认的镜头/声音/素材，只修改对应秒段，再扩展 45–90 秒和多个平台比例。

每次交接更新 HANDOFF.md：锁定片段、声线参数、素材来源、下一轮需要改的秒数；不用每次全盘重做。

## 6. 发布 KPI 与质量验收

发布前检查：3 秒是否看懂场景；15 秒是否看懂真实操作和结果；是否有断层、黑屏、裁切、乱字幕、泄露隐私、虚构数据；画面、声线、音乐授权是否满足平台规则。9:16 和 16:9 单独检查 UI 可读性，不要仅靠裁剪。

发布后跟踪：3 秒留存、平均观看时长、完播率、主页点击、GitHub 浏览/Star、官网试用、咨询线索。不要把曝光等同于成交。没有实际视频样本之前，不宣称验证过商业转化。
